BUS-001	硬性	业务SQL内容审核	通用	业务 SQL 中禁止包含任何数据定义语言（DDL）操作，包括但不限于 TRUNCATE、CREATE、ALTER、DROP、RENAME、COMMENT、GRANT、REVOKE。也禁止通过动态 SQL 拼接后在业务 SQL 中执行 DDL。适用范围仅限业务 SQL，不包含数据库对象内部定义	1、检查业务 SQL 文本中是否出现 TRUNCATE、CREATE、ALTER、DROP、RENAME 等 DDL 关键字；2、忽略字符串常量、注释中的关键字，避免误报；3、检查动态 SQL 拼接内容，若其中包含 DDL 关键字同样判定违规；4、CREATE TABLE被允许，应判定为合法；5、仅检查业务 SQL 本身，不检查存储过程、函数等对象内部定义。	业务 SQL 中直接包含 DDL 语句，属于高危操作，可能引发锁表、数据丢失或意外结构变更。	去除 DDL 语句，将结构变更操作移交 DBA 或运维通过变更流程执行；如确需清理数据，改用 DELETE 并分批提交。
BUS-002	硬性	业务SQL内容审核	通用	业务 SQL 中的 SELECT、DELETE 和 UPDATE 语句必须包含有效的 WHERE 条件，用于限定查询或实际操作的数据范围。仅包含恒真条件（如 WHERE 1=1）且无其他实际过滤条件的，视为无效 WHERE，属于违规。若 WHERE 中包含具体过滤条件（如 id=?、status=?），即使同时存在 1=1，也不视为违规。	检查 SELECT、DELETE 和 UPDATE 是否包含 WHERE 及实际过滤条件；仅由恒真条件组成时判定违规；仅检查业务 SQL 本身	SELECT、DELETE/UPDATE 缺少有效 WHERE 条件，可能导致全表扫描或对全表执行删除、更新操作。	为 SELECT、DELETE/UPDATE 添加具体业务过滤条件（如主键、唯一键或明确的业务状态），确保仅查询或影响目标数据范围。
BUS-003	建议	业务SQL内容审核	通用	业务 SQL 中建议避免使用 SELECT * 进行查询，应尽量显式列出所需字段。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 SELECT 列表中的 *、表名.* 或别名.*；忽略字符串常量和注释；仅检查业务 SQL 本身	使用 SELECT * 未显式指定查询字段，返回列不明确，可能包含不需要的列。	建议将 SELECT * 改为显式列出实际需要的字段名。
BUS-004	硬性	业务SQL内容审核	通用	业务 SQL 中必须使用绑定变量占位符（如 ?、:name、$1 等），禁止在 SQL 语句中直接硬编码常量值。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查查询条件、更新值或插入值中的硬编码常量；检查绑定变量占位符；忽略 SQL 标识符；仅检查业务 SQL 本身	SQL 中硬编码常量值，无法复用执行计划，且存在 SQL 注入风险。	将硬编码的常量值替换为绑定变量占位符，由程序参数传入实际值。
BUS-005	硬性	业务SQL内容审核	通用	业务 SQL 中判断 NULL 值时，必须使用 IS NULL 或 IS NOT NULL，禁止使用 = NULL、!= NULL 或 <> NULL 进行比较。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查与 NULL 比较的表达式；出现 = NULL、!= NULL 或 <> NULL 判定违规；仅检查业务 SQL 本身	使用 = NULL 或 != NULL 比较 NULL 值，比较结果恒为 UNKNOWN，无法正确过滤数据。	将 = NULL 改为 IS NULL，将 != NULL 或 <> NULL 改为 IS NOT NULL。
BUS-006	建议	业务SQL内容审核	通用	业务 SQL 中建议尽量避免使用 NOT、!=、<>、NOT EXISTS、NOT IN 等负向查询条件，优先考虑使用正向条件或等价改写。适用范围仅限业务 SQL，不包含数据库对象内部定义。	1、检查 WHERE 子句中是否出现 NOT、!=、<>、NOT EXISTS、NOT IN 等负向查询关键字或运算符；2、若出现，则给出优化建议，不判定为违规；3、忽略字符串常量、注释中的关键字，避免误报；4、仅检查业务 SQL 本身。	使用负向查询可能导致SQL不走索引、全表扫描，影响查询性能。	建议改写为正向条件，如使用 IN 替代 NOT IN（需注意 NULL 值处理），或使用 EXISTS 替代 NOT EXISTS 等。
BUS-007	硬性	业务SQL内容审核	通用	业务 SQL 中，对于同一字段的多个等值条件使用 OR 连接时，必须改写为 IN() 形式。不同字段之间的 OR 不适用此规则。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查同一字段通过 OR 连接多个等值条件；不同字段不判定；忽略字符串常量和注释；仅检查业务 SQL 本身	同一字段使用多个 OR 进行等值判断，SQL 可读性差，且不利于优化器有效利用索引。	将同一字段的多个 OR 等值条件改写为 IN() 形式，如 col IN (value1, value2, ...)。
BUS-008	硬性	业务SQL内容审核	通用	业务 SQL 中禁止使用前导通配符的 LIKE 查询，即 LIKE 模式字符串以 % 开头，包括 LIKE '%xx' 和 LIKE '%xx%'。仅允许后缀匹配（如 LIKE 'xx%'）。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 LIKE 模式字符串是否以 % 开头；忽略字符串常量和注释中的 LIKE；仅检查业务 SQL 本身	LIKE 使用前导通配符（% 开头）无法利用索引，导致全表扫描。	避免使用前导通配符，改为后缀匹配（'xx%'）；如确需模糊搜索，可考虑使用全文索引或专用搜索引擎
BUS-009	硬性	业务SQL内容审核	通用	业务 SQL 中，单个查询块内通过 FROM 和 JOIN 引用的表总数（含同表不同别名按实际数量计数）不得超过 3 张。适用范围仅限业务 SQL，不包含数据库对象内部定义。	统计每个查询块 FROM 和 JOIN 引用的表；同一物理表不同别名按多个表计数；忽略字符串常量和注释；仅检查业务 SQL 本身	单个查询中 JOIN 涉及表数量超过限制，查询复杂度高，易导致执行计划劣化。	将多表关联查询拆分为多个简单查询，或减少不必要的关联表，也可通过增加冗余字段或汇总表降低关联数量。
BUS-010	建议	业务SQL内容审核	通用	业务 SQL 中建议使用 ANSI JOIN 语法（如 INNER JOIN、LEFT JOIN、RIGHT JOIN 等），避免使用逗号分隔的隐式连接。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 FROM 子句中的逗号分隔隐式连接；忽略字符串常量和注释；仅检查业务 SQL 本身	使用逗号分隔的隐式连接，连接条件不明确，SQL 可读性差，可能产生笛卡尔积。	建议将逗号分隔的隐式连接改写为显式 ANSI JOIN 语法，如 INNER JOIN ... ON 条件或 LEFT JOIN ... ON 条件。
BUS-011	硬性	业务SQL内容审核	通用	业务 SQL 中禁止使用 SELECT ... FOR UPDATE、SELECT ... FOR SHARE、LOCK IN SHARE MODE 等显式加锁语句。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 FOR UPDATE、FOR SHARE、LOCK IN SHARE MODE 等关键字；忽略字符串常量和注释；仅检查业务 SQL 本身	业务 SQL 中使用显式加锁，容易造成锁等待、死锁，影响并发性能。	去除显式加锁语句，改用乐观锁、版本号或事务隔离级别等其他并发控制方案。
BUS-012	硬性	业务SQL内容审核	通用	业务 SQL 中，单条 INSERT 语句使用 VALUES 列表插入多行时，单次 VALUES 的元组数量不得超过 5000 个。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 INSERT VALUES 子句的元组数量；INSERT ... SELECT 不适用；忽略字符串常量和注释；仅检查业务 SQL 本身	单次 INSERT 的 VALUES 元组数量超过限制，事务过大，锁持有时间长，影响并发性能。	将超过 5000 个元组的批量 INSERT 拆分为多个批次，每批不超过 5000 个，并分批提交。
BUS-013	硬性	业务SQL内容审核	通用	业务 SQL 中禁止使用 RAND()、RANDOM()、DBMS_RANDOM.VALUE 等随机函数作为 ORDER BY 排序表达式。适用范围仅限业务 SQL，不包含数据库对象内部定义。	检查 ORDER BY 中的 RAND()、RANDOM()、DBMS_RANDOM.VALUE；忽略字符串常量和注释；仅检查业务 SQL 本身	使用随机函数进行排序，会导致全表扫描和随机排序，性能开销大，结果不确定。	去除 ORDER BY 中的随机函数，如需随机抽样，改为在应用层生成随机条件或使用限定的随机值筛选。
BUS-014	建议	业务SQL内容审核	通用	业务 SQL 中，WHERE、JOIN、ORDER BY、GROUP BY 等子句涉及的条件列，应确保在数据模型中存在可用索引。审核时需依赖表结构和索引信息（数据模型）进行判断。适用范围仅限业务 SQL，不包含数据库对象内部定义。	提取 WHERE、JOIN ON、ORDER BY、GROUP BY 条件列并结合数据模型检查匹配索引；未提供数据模型时标记待人工确认或提示补充模型；忽略字符串常量和注释；仅检查业务 SQL 本身	条件列缺少可用索引，可能导致全表扫描，影响查询性能。	为条件列创建合适的索引，或调整查询条件以利用现有索引；若无法确认索引情况，请补充数据模型后重新审核。
